Three Core Engineering Pillars

  1. Bangla & Banglish Voice-to-Confirmed-Ledger: A landlord speaks naturally—"Flat 3B er Rahim bhai 8000 taka bKash korse". Groq Whisper Large V3 Turbo transcribes the audio in-memory into editable Bangla text; a pinned OpenRouter model extracts strict Zod-validated JSON; deterministic backend code resolves the exact unit and tenant (never guessing on ambiguous matches); and an explicit Confirmation Card gates every financial write and SMS.
  2. Deterministic, Immutable Financial Accounting: Every taka is stored in PostgreSQL BIGINT *_paisa columns (zero floating-point math). Balances are never stored as fragile "Paid/Unpaid" booleans; they are computed dynamically from rent_obligations minus SUM(payment_allocations). Confirmed payments are never deleted—corrections create auditable negative reversal entries.
  3. Production-Ready Banglalink AppLink SMS: Confirmed payment receipts and overdue reminders are sent via https://api.applink.com.bd/sms/send through an HMAC-SHA256 authenticated Oracle Cloud Always Free Static-IPv4 Relay, permanently solving AppLink's E1303 IP-whitelisting requirement while keeping hackathon hosting at $0/month.

Problem Statement

Small residential landlords in Bangladesh (2–20 units) operate micro-businesses without accountants or ERP teams. Interviews and market observation reveal four structural pain points that cause monthly revenue leakage and landlord-tenant friction:

1. Partial-Payment & Balance Drift

Tenants frequently split a ৳12,000 rent into ৳8,000 via bKash on the 5th and ৳4,000 cash on the 15th. Paper khatas and simple "Paid/Unpaid" toggles fail immediately on multi-installment payments and multi-month arrears.

2. Form Fatigue for Non-Tech Landlords

Many residential building owners are aged 45–70 and find multi-screen English ERP forms slow and intimidating, causing them to abandon software within 2 weeks and return to notebooks.

3. Missing Receipts & Awkward Chasing

Landlords rarely issue written receipts for partial cash or bKash transfers, leading to disputes at move-out. Chasing late rent by personal phone call is socially uncomfortable.

4. Zero Expense vs. Income Visibility

Plumbing repairs, water pump maintenance, and caretaker salaries are paid out of pocket without linking to property income, leaving landlords blind to true net operating yield.

Proposed Solution: Safe Bangla Voice + Verified Ledger

RentReady AI is a mobile-first, bilingual (বাংলা / English) rental operations SaaS where touch UI and conversational Bangla voice work seamlessly together over a single deterministic PostgreSQL ledger.

The 9-Step Human-in-the-Loop Bangla Voice Pipeline

1. Mic Capture (Browser MediaRecorder) OR Direct Bangla/English Text Fallback 2. Replaceable Bangla ASR (Groq Whisper Large V3 Turbo — audio discarded in memory) 3. Editable Transcript UI (Landlord fixes any misheard name or Taka amount) 4. Pinned OpenRouter JSON Extraction (temperature=0, strict system contract) 5. Zod Schema Validation (Rejects negative amounts, missing fields, malformed JSON) 6. Deterministic DB Entity Resolution (Exact unit + tenant match; NEVER guesses) └─ If 2 tenants named "Rahim" exist → returns `needs_clarification` radio picker 7. Explicit Confirmation Card (Shows resolved Tenant, Unit, BDT, Remaining Balance / SMS) 8. Deterministic Backend Execution (Idempotent PostgreSQL RPC or Confirmed AppLink SMS) 9. Append-Only Audit Log (Links voice_action_id → executed_record_id → audit_logs)

8 Structured Voice Action Contracts

Write & SMS Actions (Confirmation Mandatory)

  • record_rent_payment — Full/partial payment (cash/bKash/Nagad/bank)
  • record_expense — Property repair, utility, or staff expense
  • create_maintenance_request — Log unit issue with priority
  • prepare_rent_reminder — Draft & confirm AppLink SMS reminder

Read-Only Queries (Instant DB-Computed)

  • get_outstanding_rent — Exact due list per unit/tenant/month
  • get_monthly_collection — Expected vs. collected vs. remaining
  • get_payment_history — Chronological tenant ledger
  • get_property_summary — Occupancy, net income, open repairs

Complete Core Operations (Touch UI + Voice Parity)

  • Properties & Units: Fast setup (auto-creates default building), unit rent configuration, vacant/occupied status tracking.
  • Tenants & Tenancies: Normalized Bangladesh phone numbers (+8801XXXXXXXXX), Banglalink prefix indicator, and database-enforced single active tenancy per unit.
  • Immutable Financial Ledger: 1-click monthly bill generation, partial/full payment allocation, immutable reversals with reason, and instant AppLink SMS receipts.
  • Executive Dashboard: 100% database-computed KPIs (Expected, Collected, Outstanding, Expenses, Net Operating Result, Occupancy %) with zero client-side financial guesswork.

Technical Implementation & Security Architecture

RentReady AI is engineered as a strictly typed TypeScript modular monolith (pnpm workspace) designed for low latency, zero-cost hackathon execution, and effortless transition to commercial production without a rewrite.

[Mobile/Desktop SPA: React 19 + Vite + Tailwind v4 (Bangla/English)] │ HTTPS + Supabase User JWT (Same Origin via Cloudflare Workers Static Assets) ▼ [Cloudflare Worker: Hono REST API (apps/api)] ├──► [Supabase PostgreSQL + Auth + 100% RLS (19 Tables, BIGINT *_paisa, Atomic RPCs)] ├──► [Groq Whisper Large V3 Turbo (In-Memory Bangla ASR) + OpenRouter Pinned LLM] └──► HMAC-SHA256 + 60s Replay Guard ──► [Oracle Cloud Always Free Static-IP Relay] │ (Whitelisted Static IPv4) ▼ [Banglalink AppLink SMS API]

Financial Ledger Invariants

  • Zero Floats: All money stored in BIGINT *_paisa (1 BDT = 100 paisa) with BigInt string parsing.
  • Derived Balances: v_obligation_balances computes outstanding dues from rent_obligations minus SUM(payment_allocations).
  • Idempotent Atomic RPCs: record_payment_atomic & reverse_payment_atomic enforce UNIQUE(landlord_id, idempotency_key).

Security & Multi-Tenant Isolation

  • 100% RLS Coverage: Every table (19/19) enforces landlord_id = auth.uid(); views use security_invoker = true.
  • Zero service_role in User Routes: Worker forwards caller's Supabase JWT directly to PostgreSQL.
  • Append-Only Ledger & Audit: Zero UPDATE/DELETE RLS policies on payments, payment_allocations, and audit_logs.

Automated Quality Verification (GitHub Actions CI)

Every commit runs strict TypeScript checks, Vite production builds, and 33 automated Vitest tests covering integer money math, SQL migration RLS/no-float invariants, ambiguous voice entity rejection, HMAC signature verification, and HTTP 200 AppLink error parsing (E1303 / E1313).

Banglalink AppLink Integration: APIs & User Flows

AppLink is embedded directly into RentReady AI's core financial loop—turning every recorded rent payment and overdue balance into an instant, auditable telco communication channel.

1. APIs Integrated & Production Roadmap

AppLink API Endpoint RentReady AI Use Case Stage
SMS MT API POST https://api.applink.com.bd/sms/send Confirmed Bangla/English payment receipts (with remaining balance) & polite overdue rent reminders Live in MVP (Release A)
OTP API POST /otp/request & /otp/verify Banglalink landlord phone verification & high-value reversal confirmation Enhancement Sprint (6–16 Dec)

2. Solving the Cloudflare-to-AppLink Fixed-IP Blocker (E1303)

Official AppLink authentication requires every API POST to originate from an explicitly whitelisted static IPv4 address (otherwise returning E1303). Because Cloudflare Workers operate over Anycast with rotating outbound IPs, direct Worker-to-AppLink calls fail in production. We engineered a clean, zero-cost solution:

  • apps/api signs each confirmed SMS payload with HMAC-SHA256 + a 60-second timestamp window using Web Crypto.
  • services/applink-relay (Dockerized Node 22 / Hono service on an Oracle Cloud Always Free VM) verifies the signature, enforces a hardcoded allowlist strictly to https://api.applink.com.bd/sms/send (preventing SSRF), injects server-side applicationId + password, and dispatches from our single whitelisted static IPv4.

3. Telco-Grade Error Handling & User Flow (Per Applink-as-a-Skill)

Landlord records ৳8,000 payment (Unit 3B) OR clicks "SMS Reminder" on Overdue List └─► Confirmation Modal opens (shows recipient +88019..., editable Bangla/English SMS) └─► Landlord clicks "Confirm & Execute" (sends confirmed:true + idempotency_key) └─► Worker checks duplicate key ─► Signs & calls OCI Static-IP Relay └─► AppLink POST /sms/send ─► Parses JSON body (NEVER trusts HTTP 200 alone!) ├─ statusCode === "S1000" ─► status="sent", logs requestId └─ E1303 / E1313 / other ─► status="failed", logs sanitized code

Operator Transparency: Because AppLink natively serves Banglalink subscribers (+88019 / +88014), RentReady AI automatically detects recipient prefixes, displays a clear compatibility indicator, and offers a 1-click "Copy Receipt Text" fallback for non-Banglalink numbers until our multi-operator BD SMS aggregator launches in Release C.
